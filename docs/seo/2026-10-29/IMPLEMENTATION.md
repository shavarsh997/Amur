# SEO-аудит SHINEX и внедрение — 29 октября 2026

**Готово локально, не опубликовано. Все 120 индексируемых URL сохранены.** До внедрения составлены [карта запросов, конфликты и риски](AUDIT_AND_PLAN.md). Изменения дополняют существующую архитектуру и не отменяют работу 26–28 октября.

## Основной вывод

Свежая Excel-выгрузка содержит отдельные листы запросов и страниц, но не пары query + page. Доказать вредную конкуренцию страниц по ней нельзя. Самостоятельные страницы уже имеют поисковый трафик; массовые объединения были бы неоправданным риском. В карте найден и устранён конкретный редакционный конфликт: одинаковые запросы «строительная компания» назначались главной и строительству домов во всех пяти языках. Это конфликт назначения в проекте, а не доказанная потеря позиций Google.

По исходной карте проверены 24 семейства страниц × 5 языков. Полный инвентарь — [187 обнаруженных URL и 16 файлов маршрутов](URL_INVENTORY.md); он включает canonical страницы, существующие aliases, неопубликованные маршруты и технические ресурсы. JSON хранит title, description, H1, canonical, клики, показы, CTR и позицию точной строки GSC. `DEEP_BEFORE.json` и `DEEP_AFTER.json` содержат H1–H3, внутренние ссылки и глубину переходов каждого canonical URL. Оценки IMPROVE/INVESTIGATE в инвентаре — редакционные решения; точный список внесённых изменений приведён ниже.

## Сохранённые страницы и сигналы

На всех **120 URL** автоматически сравнены и сохранены: status, title, meta description, H1, self-canonical, HTML-язык, hreflang и robots. Подтверждение — `PRESERVATION_CHECK.json`. Параметры не попадают в canonical; языковые страницы не каноникализируются друг на друга. В sitemap прежние 120 URL; `lastModified` обновлён только для трёх семейств с существенными дополнениями текста, всего 15 URL.

Следующие 14 семейств / 70 URL сохранены без изменения основного содержания:

- `/prices`, `/calculator`, `/about`, `/contacts`, `/privacy`.
- `/services/renovation`, `/services/house-construction`, `/services/interior-design`, `/services/commercial-construction`.
- `/services/design`, `/services/monolithic-work`, `/services/facade-and-roofing`, `/services/plumbing-work-yerevan`, `/services/electrical-work-yerevan`.

Семь базовых услуг, девять специализированных услуг, страницы цены/сметы и базовые маршруты остаются самостоятельными. Существующие 25 локализованных redirects не изменены. Новых удалений, объединений, URL, redirect или noindex нет. Неопубликованные блог и демо-проекты уже были 404 до этой работы.

**Предложений к немедленному объединению — 0.** Для дальнейшего наблюдения оставлены пары общий/квартирный дизайн, коммерческий/офис, общий ремонт/под ключ. Без query + page, выбранного canonical, истории и внешних ссылок они не являются кандидатами на исполнение миграции. Любое будущее обоснованное слияние требует отдельного согласования, переноса полезного материала и 301 с сохранением языка.

## Проверки

- Production build Next.js 16.2.11: успешно; 138 результатов сборки, из них 120 индексируемых страниц. TypeScript проверен сборкой. Использованы локальные руководства Next.js по Metadata API и sitemap.
- `npm run seo:check`: успешно. Проверены конфигурация URL, полные переводы, уникальность метаданных, owner запроса, references, self/reciprocal hreflang, индексируемость production и защита preview.
- Обход опубликованного сайта **до изменений**: 120 canonical страниц, 50 вариантов существующих retired URL, корень, 5 slash-редиректов и 30 контрольных 404. Доказательство — `HTTP_LIVE.json`.
- Локальные обходы до и после: все 120 URL — 200; по одному H1/title/description; нет точных дублей title/description/H1. Проверены robots, заголовки индексации, sitemap, hreflang, JSON-LD, внутренние ссылки и фрагменты. `HTTP_BEFORE.json`, `HTTP_AFTER.json`.
- Заголовки всех страниц: пропусков уровней нет. Все canonical URL достижимы за один переход с соответствующей языковой главной с учетом общей навигации. Только privacy не имеет входящих ссылок из основного текста; ссылка footer присутствует, orphan-страниц нет. `DEEP_AFTER.json`.
- Текстовая похожесть услуг: сравнение пятисловных шинглов в пределах каждого языка; максимальные исходные показатели Jaccard около 0,7–1,35%. Буквальные дубли этим методом не выявлены; семантическое пересечение и каннибализацию он не доказывает. `before/CONTENT_SIMILARITY.json`, `CONTENT_SIMILARITY.json`.
- Браузер: 25 страниц на пяти языках при 320 и 1280 px, 50 проверок. Один H1, без горизонтального переполнения документа, ошибок консоли не обнаружено. Визуально проверены русский каталог и немецкая мобильная карточка. Проверен путь каталог → капитальный ремонт → цены → смета → выбор связи → загруженная форма. Заявка не отправлялась. `BROWSER_CHECKS.json`.
- После финального уточнения расположения примера сметы повторены build, полный HTTP-обход, сравнение сохранённых SEO-сигналов и 10 браузерных проверок сметы (5 языков × 2 ширины), без ошибок.

На внешнем хостинге сохранена ранее существующая цепочка HTTPS → www → HY для входа с HTTP без www; максимально три 308. На canonical host alias/slash нормализуются за один переход. Данные — `LIVE_REDIRECTS.json`. Изменение доменной конфигурации требует отдельной задачи; приложение уже объединяет свои правила.

## Что ещё требуется после выпуска

Доступ к GSC URL Inspection и совместным query + page не предоставлен. Semrush не выдал внешние ссылки из-за недостатка API units. Поэтому фактическая индексация, выбранный Google canonical, внешние ссылки и влияние на позиции остаются непроверенными. Текущие HTTP-тесты не выдают их за подтверждённые.

Порядок наблюдения, конкретные запросы, API/export-рецепт, сравнение сопоставимых периодов и условия отката — [GSC_MONITORING.md](GSC_MONITORING.md). После штатного выпуска повторить production-обход, проверить переобход и canonical ключевых страниц, затем оценивать 28 полных дней после переобхода и устойчивость через 6–8 недель. Оценивать клики и заявки всего кластера, а не только позицию отдельного URL.

## Воспроизведение

```bash
python3 scripts/seo-gsc-baseline.py /path/to/shinex.am-Performance-on-Search-2026-10-29.xlsx --output docs/seo/2026-10-29/GSC_BASELINE.json
npm run build
npm run start -- --hostname 127.0.0.1 --port 3106
```

В другом терминале; Python для импорта должен иметь pandas и Excel-reader:

```bash
npm run seo:check -- --base-url http://127.0.0.1:3106 --report docs/seo/2026-10-29/HTTP_AFTER.json
node scripts/seo-quality-audit.mjs docs/seo/2026-10-29/DEEP_AFTER.json
node scripts/seo-inventory.mjs docs/seo/2026-10-29/HTTP_AFTER.json docs/seo/2026-10-29/GSC_BASELINE.json docs/seo/2026-10-29
```

После публикации новую сборку можно проверить той же командой `seo:check` с `--base-url https://www.shinex.am` и отдельным именем отчёта. До публикации проверка точного совпадения новых текстов с production закономерно не пройдёт.
