Внешняя проверка страницы https://www.shinex.am/hy/prices подтверждает опубликованную ставку от 55 000 драм/м² и текущее описание бюджета. Semrush недоступен: недостаточно API units. Не получены SERP с армянской геолокацией, query + page, внешние ссылки, фактические лиды, GA4, URL Inspection, CrUX. Их значения не подменяются предположениями.

Повторный проход включает прямой HTTP-обход опубликованного сайта: `HTTP_LIVE.json`, 120 страниц, 50 вариантов retired URL, корень, 5 языковых slash-редиректов и 30 контрольных 404. Он проведён отдельно от локального `HTTP_AFTER.json`, без требования совпадения ещё не опубликованных текстов. Проверка host/protocol — `LIVE_REDIRECTS.json`. Публичный Google PageSpeed API для `/hy/prices`, mobile, вернул HTTP 429: показатели производительности из этого запроса не получены.

## Что уже корректно

- 120 canonical URL в sitemap: 24 страницы × 5 языков. Контент генерируется на сервере; основные маршруты статические.
- Каждая языковая версия имеет свой canonical, взаимные hreflang и x-default на HY. Query-параметры не включены в canonical.
- `/` перенаправляется 308 на `/hy`. Уже есть 5 правил retired URL × 5 языков; домен, slash и alias объединены proxy в один шаг. На опубликованном Vercel перед proxy обнаружены отдельные HTTPS/www переходы; подробности в плане миграций.
- Коммерческие страницы индексируемы в production; preview/dev получают noindex. Robots не блокирует ресурсы рендеринга.
- Organization / LocalBusiness, Service и BreadcrumbList используют данные компании. Фиктивные рейтинги не обнаружены.
- Демо-портфолио и пустой блог уже не опубликованы; проекты возвращают 404. Не публиковать стоковые или сгенерированные изображения как выполненные работы.

## Подтверждённые проблемы и приоритеты

1. **P1 — измерение заявок.** `form_start` вызывается каждым фокусом. Нет событий фактической доставки, ошибки доставки и взаимодействия с калькулятором. Телефонные/WhatsApp ссылки не вызывают объявленные события. Без baseline лидов эффективность SEO не измерить.
2. **P1 — атрибуция.** Обычная заявка не передаёт посадочную страницу/источник. Калькулятор задаёт источник как `/calculator`, даже если открыт с другой страницы. Нужны безопасные идентификаторы страниц и канала, без контактов клиента в GA.
3. **P1 — цены.** Подтверждена стартовая ставка, но точный пакет, материалы, сроки и тарифы по типам не подтверждены. Нужны явно учебные примеры 40/60/80 м² и объяснение условий. Нельзя назвать ставку ценой только труда или обещать включённые материалы без владельца.
4. **P2 — мобильные контакты и навигация.** На мобильном контакт скрыт за меню, телефон — ниже по странице. Цена — приоритетный интент, заслуживает прямой ссылки в навигации. Добавить быстрые телефон/WhatsApp/заявку без перекрытия контента.
5. **P2 — связи внутри ремонта.** Основная квартирная страница объясняет капитальный и косметический ремонт, но не даёт прямых ссылок на эти страницы. Связать основной выбор, цены и смету.
6. **P2 — доверие.** Есть единый телефон, email, адрес, часы, зона обслуживания; офис не принимает посетителей. Нет подтверждённых кейсов, отзывов, юрлица, гарантий и сертификатов. Нужны реальные материалы, а не новые обещания.
7. **P2 — контекст расчёта.** CTA общей и квартирной страницы дизайна открывал калькулятор со строительством. Исправлено: allowlist сценариев в query, выбранный дизайн после перехода, прежний canonical без параметров. Сам калькулятор и основное содержимое остаются SSG; динамический выбор из URL вынесен в малый Suspense-компонент. Проверено на пяти языках.
8. **P2 — точность семантики и перелинковки.** Общая карта дизайна повторяла квартирные запросы; они перенесены в цель квартирной посадочной. Общая квартирная страница больше не назначена целевой для специализированных запросов капитального/косметического ремонта. С квартирного дизайна добавлена связь с ремонтом квартиры вместо ремонта частного дома, с офисной страницы — с электрикой. HY descriptions отдельных услуг конкретизированы по существующему составу работ; HY/RU монолитные работы получили описание опалубки, армирования, бетонирования и исходных данных для сметы.

## Каннибализация: анализ намерения

`services/renovation` уже представляет ремонт **частных домов**, а не квартир. Его slug исторический, содержание различается: сохраняем. Главная квартирная страница — `services/apartment-renovation-yerevan`. Новостройки имеют передачу от застройщика/черновые этапы; капитальный ремонт — замена систем/оснований; косметический — сохранение систем/обновление покрытий. Эти задачи сохраняются на всех пяти языках.

`turnkey-renovation` описывает координацию, закупки и границы проекта. Есть частичное пересечение с квартирной страницей, но это не доказанная каннибализация. Сохраняем, усиливаем различие. `apartment-interior-design-yerevan`/`interior-design` и `office-renovation-yerevan`/`commercial-construction` — кандидаты INVESTIGATE, без автоматического объединения.

`prices` отвечает на стоимость; `renovation-estimate-yerevan` — на структуру сметы и её получение; `calculator` — запрос расчёта строительства/дизайна. Автоматический расчёт ремонта намеренно недоступен. `renovation-price-per-square-meter-yerevan` уже перенаправлен на `prices`. Никаких новых дублей или замен canonical на noindex не требуется.

Для доказательства пересечения экспортировать query + page + date, отдельно язык, страну и устройство. Сравнить доли показов/кликов URL одного запроса по неделям и намерения в локальной выдаче. Проверить выбранный Google canonical и внешние ссылки до миграции. Низкие клики сами по себе не основание для удаления.

## Производительность и проверка

До изменений локальная production-сборка и HTTP-обход (`HTTP_BEFORE.json`) подтвердили 120 ответов 200, отсутствие точных дублей title/description/H1 и отсутствие страниц без входящих ссылок из того же языка. 50 вариантов старых адресов со slash/без slash дали 308, 15 контрольных отсутствующих страниц — 404. Похожесть основного текстового содержимого услуг отдельно рассчитана по пятисловным шинглам в `CONTENT_SIMILARITY.json`: буквальные дубли не выявлены. Низкая текстовая схожесть не исключает пересечение намерений.

Изображения услуг имеют локальные WebP, alt, responsive sizes; существующие тесты проверяют размеры файлов и иллюстративные подписи. Используются системные шрифты. Числа LCP/CLS/INP не выводятся из размера HTML или локального build. В итоговом отчёте отдельно будут результаты HTTP-crawl, проверок интерфейса и ограничения полевых метрик.

Методика canonical/hreflang: [Google canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [локализованные версии](https://developers.google.com/search/docs/specialty/international/localized-versions).
