# Данные владельца и внешнее локальное SEO

## Что нужно подтвердить для контента

- **Цена от 55 000 драм/м²:** точный состав базовых работ, включены ли какие-либо материалы, единица площади, условия применения, дата актуальности. До подтверждения опубликованы только существующая ставка и условные арифметические примеры. Новые тарифы по типам ремонта не добавлены.
- Тарифы отдельных операций и материалов; реальные сроки по типам объектов. Сейчас это индивидуальная смета и факторы сроков, без вымышленных диапазонов.
- Юридическое название, регистрационные данные, ответственные лица, подтверждённые условия договора и гарантии. Не заполнять числовыми или рекламными обещаниями без документов.
- Для каждого реального кейса: согласие на публикацию, оригинальные фото до/процесс/после, тип работ, площадь, населённый пункт без частного адреса клиента, исходная задача, согласованные этапы и результат. Ввести данные в существующие модели после проверки; создать индексируемый кейс только с достаточным содержимым.
- Реальные отзывы с разрешением и источником. Не добавлять фиктивные звёзды/aggregateRating. Существующие картинки не выдавать за проекты SHINEX.
- Проверить новый армянский текст носителем языка. Подтвердить обновлённую политику конфиденциальности и дату публикации.

## Внешние действия

1. Google Business Profile: проверить владение, точное имя SHINEX, телефон +374 55 15 66 15, сайт, часы Пн–сб 09:00–19:00, реальные категории и географию. В конфигурации `acceptsVisitors:false`: не обещать публичный приём в офисе и сверить настройки адреса/зоны обслуживания с реальной работой компании.
2. Добавить собственные фото команды, процесса и завершённых работ. Согласовать использование каждой фотографии.
3. Просить реальных заказчиков оставить отзыв после завершения работ, без покупки отзывов и фильтрации только довольных клиентов. Отвечать на отзывы от компании.
4. Сверить имя, телефон, сайт и режим в реальных локальных справочниках и социальных профилях. Удалить только подтверждённые дубли карточек; массовые каталоги и обмен ссылками не нужны.
5. GSC: после штатного выпуска проверить URL Inspection для HY/RU prices, apartment-renovation, new-build, house-construction; отправить sitemap. Проверить выбранные Google canonical, redirects и индексируемость.
6. Получить GSC query + page + date (по необходимости country/device) за 3 месяца и список внешних ссылок перед любым спорным слиянием. Экспорт не должен трактоваться как все поисковые запросы рынка.
7. Настроить GA4 по `ANALYTICS_SETUP.md`. Реальную тестовую заявку после выпуска отправляет владелец и подтверждает получение менеджером. Текущие автоматические тесты используют mock.
8. Вести учёт квалифицированных лидов: дата, канал, посадочная, услуга, регион, стадия, причина нецелевого обращения. Контактные данные остаются в рабочей системе компании, не в GA4/GSC.
9. Проверить production Core Web Vitals в Search Console/CrUX, отдельно мобильные. Если недостаточно полевых данных, не объявлять прохождение CWV; дополнить лабораторным Lighthouse и реальными устройствами. После накопления данных смотреть p75 LCP/CLS/INP, а не среднее локального теста.
10. При выпуске проверить настройки доменов Vercel: публичная цепочка HTTP без www → HTTPS без www → HTTPS/www → конечный URL подтверждена в `LIVE_REDIRECTS.json`. Код proxy объединяет редиректы, когда запрос доходит до приложения; текущие доменные правила платформы выполняются раньше. Сократить лишний www/alias шаг, сохранив HTTPS, и повторить проверку всех четырёх комбинаций. Прямые ссылки сайта уже используют canonical назначения.

Действия с внешними аккаунтами, публикацией сайта и сообщениями клиентам в текущей работе не выполнялись.
