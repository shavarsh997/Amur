# Оптимизация по отчёту PageSpeed — 14 октября 2026

Изменения сделаны в исходниках, без публикации. Основание — присланный отчёт для `/hy`: 3,2 с работы основного потока, 588 мс CPU у Google Analytics, 86 мс принудительной компоновки без указания источника. Ожидаемая экономия от CSS в отчёте — 50 мс.

## Что изменено

- В клиентское окно контактов передаются только нужные разделы перевода вместо полного словаря сайта. На странице контактов `ContactMethods` получает только контактные подписи.
- Код формы заявки загружается при открытии формы через `React.lazy`. Во время загрузки видны локализованный статус и работающие кнопки возврата/закрытия. Основной контент сайта по-прежнему отрисовывается на сервере.
- При инициализации появления секций все размеры читаются до изменения стилей. Контроллер фонового строительства сохраняет размеры страницы и использует позицию прокрутки без `getBoundingClientRect()` на каждом scroll. Размеры обновляются при resize, изменениях высоты страницы/шапки, восстановлении страницы и возврате во вкладку.
- Внешний Google Analytics переведён на `lazyOnload`: после загрузки страницы и в свободное время браузера. Короткая инициализация очереди событий осталась `afterInteractive`. Аналитика не удалена. Очень короткий визит, завершившийся до загрузки внешнего скрипта, может не попасть в GA.
- Импорты глобального CSS сосредоточены в locale layout. В production остаются два CSS-файла: стили, необходимые для первого отображения, намеренно не переводились на асинхронную загрузку.

В эти суммы не входят GA, изображения, prefetch и позднее загружаемая форма. Уменьшение HTML на 21% не означает ускорение всей страницы на 21%.

## Проверки

- Production build и TypeScript: успешно, 138 генерируемых маршрутов/служебных результатов.
- Сравнение 132 HTML-документов: набор страниц, язык, title, метатеги, canonical/hreflang, заголовки, текст, адреса ссылок и JSON-LD совпадают до/после. HTML-контент не скрыт за клиентской загрузкой.
- HTTP SEO crawl: 120 страниц, 50 вариантов старых URL, 3 перенаправления со слешем, 15 настоящих 404, внутренние ссылки, hreflang, schema и share image — успешно.
- ESLint и `node scripts/motion-check.mjs`: проверка кода и поведения контроллеров. Тест покрывает разделение чтения/записи геометрии, отсутствие повторных измерений при обычном scroll, этапы вперёд/назад, resize, pageshow, скрытую вкладку, reduced motion и снятие обработчиков.
- Браузер: desktop `/hy`, mobile 390×844 `/ru/contacts`; открытие контактов, отложенная форма, переход назад, закрытие и восстановление прокрутки. Заявки не отправлялись. Проверены пять этажей и переход в интерьер, отсутствие горизонтального переполнения, мобильная анимация шириной 56 px в шапке.

## Что ещё показывает Lighthouse

Сигнатуры `trimStart`, `trimEnd`, `flatMap`, `fromEntries`, `at`, `hasOwn` присутствуют в поставляемом Next.js `polyfill-module.js` (сам файл 1 380 байт, 596 байт gzip). Оценка Lighthouse «11,7 КиБ устаревшего кода» не означает, что весь этот объём можно безопасно удалить из пользовательского кода. Совместимость Next.js и React не изменялась.

В отчёте 86 мс принудительной компоновки не имеют атрибуции; нельзя утверждать, что всё это время вызвано анимацией или полностью устранено. Исправлены обнаруженные в коде источники повторных измерений. Реальное изменение времени CPU и балла PageSpeed нужно проверить повторным тестом опубликованной версии в тех же условиях. В локальной проверенной конфигурации GA не включён, поэтому реальная загрузка стороннего тега и доставка событий не проверялись.

Сборка после изменений выполнена из отдельной копии исходников в `/private/tmp/shinex-performance-20261014`: обычная повторная сборка в рабочем каталоге зависла при обходе существующего `.next/server/app 3/de`. Попытки перенести старый кэш также зависли и были остановлены. Старый кэш не удалён, Git-история не менялась. Общий `git diff --stat` дополнительно выдавал ошибки чтения объектов; отдельные diff изменённых компонентов читались. Эти локальные проблемы не исправлялись в рамках оптимизации сайта.
